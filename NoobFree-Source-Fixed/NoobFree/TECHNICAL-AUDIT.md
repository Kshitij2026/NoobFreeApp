# NoobFree Technical Audit Report (Stage 1 Inspection -> v1.2.0 Fixes)

## 1. Executive Summary
Prior to modifying source files, all 56 files in `NoobFree-1.1.0-Consolidated-Reset-Glass.zip` were extracted and audited across Gradle configuration, `AndroidManifest.xml`, AIDL interfaces, Shizuku service binding, system managers, ViewModels, Jetpack Compose UI screens, and GitHub Actions CI.

## 2. Identified Root Causes & Architectural Defects in v1.1.0

| Area | Defect Identified in v1.1.0 | Root Cause in Code | Resolution Implemented in v1.2.0 |
| :--- | :--- | :--- | :--- |
| **APK Installation Conflict (`PART 11`)** | Installing a newly built APK over a prior version produced `"App not installed as package conflicts with an existing package"` (`INSTALL_FAILED_UPDATE_INCOMPATIBLE`). | `app/build.gradle.kts` set `applicationIdSuffix = ".debug"` on debug builds while release builds used `com.noobfree.android` without a signing config (`app-release-unsigned.apk`), and GitHub Actions generated a new random debug keystore on every run. | Unified `applicationId = "com.noobfree.android"`, incremented `versionCode = 3` (`1.2.0`), added env/keystore signing resolution in `app/build.gradle.kts`, and configured `.github/workflows/android-ci.yml` to sign both debug and release APKs and verify signatures via `apksigner`. |
| **Glassmorphism UI Invisible (`PART 9`)** | Only `MainActivity.kt` had a background gradient, while screens looked like flat default Material 3 pages. | Every screen (`HomeScreen`, `AppManagementScreen`, `PrivacyInspectorScreen`, `DeveloperScreen`, `DeviceInfoScreen`, `AnimationScreen`, `SettingsScreen`) wrapped content in a standard `Scaffold` and `TopAppBar` whose default opaque `MaterialTheme.colorScheme.background` covered the gradient, and `ControlCard` used a flat opaque surface without borders. | Created `GlassBackgroundCanvas` (cosmic navy/indigo/purple with radial cyan & violet orbs), `GlassScreenScaffold` (`containerColor = Color.Transparent`), `GlassSurfaceCard` (frosted translucent linear gradients + 1.dp specular gradient borders), and `GlassBottomNavigationBar`. |
| **Device Policy & Halo Detection (`PART 3 & 4`)** | `PrivacyInspectorScreen.kt` only checked `isDeviceOwnerApp` on `com.google.android.apps.work.clouddpc` and `context.packageName`, and listed any app with `"halo"` in its name with a blind Uninstall button. | No `PackageManager.queryBroadcastReceivers(Intent(ACTION_DEVICE_ADMIN_ENABLED))` scan was performed, `isDeviceOwnerApp`/`isProfileOwnerApp`/`isUninstallBlocked` were not checked on Halo packages, and no step-by-step Deactivate -> Recheck -> Uninstall state machine existed. | Built `AdminPolicyManager.kt` to inspect all installed packages and declared `BIND_DEVICE_ADMIN` receivers via [DevicePolicyManager](https://developer.android.com/reference/android/app/admin/DevicePolicyManager) and [UserManager](https://developer.android.com/reference/android/app/admin/DevicePolicyIdentifiers), distinguishing `DEVICE_OWNER`, `PROFILE_OWNER`, `ACTIVE_ORDINARY_ADMIN`, `INACTIVE_ADMIN_CAPABLE`, and `MANAGED_COMPANION`. |
| **Developer Options Without Shizuku (`PART 6`)** | Tapping "Enable Developer Options" on `HomeScreen.kt` immediately failed with `"Shizuku is not connected"`. | `HomeScreen.kt` called `viewModel.enableDeveloperOptions()` (which required Shizuku) as the primary button instead of guiding the user through Android's native 7-tap flow. | Upgraded `DeveloperManager.kt`, `HomeScreen.kt`, and `DeveloperScreen.kt` so the primary action is the **Shizuku-Independent 7-Tap Guided Workflow** (`Settings.ACTION_DEVICE_INFO_SETTINGS` + automatic `ON_RESUME` verification + `DISALLOW_DEBUGGING_FEATURES` detection), keeping Shizuku as an optional secondary shortcut. |
| **Wallpaper Failures (`PART 8`)** | Wallpaper changes failed or crashed on large images / restricted profiles. | Inline code in `AppManagementScreen.kt` did not check `WallpaperManager.isWallpaperSupported()` or `isSetWallpaperAllowed()`, lacked `RGB_565` low-RAM fallback for 2GB/3GB tablets ([Acer One 8 T4-82L Specs](https://www.bajajfinserv.in/acer-one-8-t4-82l-price-in-india)), only targeted `FLAG_SYSTEM`, and did not check if `setBitmap()` returned `<= 0`. | Created `WallpaperHelper.kt` with preflight checks (`SET_WALLPAPER`, `DISALLOW_SET_WALLPAPER`, `isWallpaperSupported`, `isSetWallpaperAllowed`), persistent URI read grants, power-of-two `inSampleSize` downsampling, `ARGB_8888`/`RGB_565` fallback, Home/Lock/Both target selection, and return-code (`> 0`) verification. |
| **App Manager & Debloating (`PART 7`)** | App list had no icons, no version numbers, no sorting, no category filters, and blocked disabling any system package (`!app.isSystem`). | `AppManagementScreen.kt` hardcoded `enabled = !protected && !app.isSystem && commandExecutor.isReady()` and lacked a safety tier classification or restore filter. | Upgraded `PackageOperationManager.kt` and `AppManagementScreen.kt` with app icon rendering, version info, 7 category filter chips (including *Safe Debloat* and *Disabled (Restore)*), 3 sort modes, active-admin uninstall interception, and a critical system denylist that protects OS/Launcher/Play Services while allowing safe bloatware disable/restore via [Shizuku](https://github.com/RikkaApps/Shizuku-API). |
| **ProGuard / R8 Release Rules** | `ShellCommandResult` Parcelable and `NoobFreeAdminReceiver` were not explicitly kept in `proguard-rules.pro`. | Missing `-keep` rules for `ShellCommandResult` and `NoobFreeAdminReceiver` when `isMinifyEnabled = true` in release builds. | Added explicit `-keep` rules in `app/proguard-rules.pro`. |
