# Android Privilege Model & Platform Limitations Reference

This document explains the Android security architecture governing **NoobFree** on personal and enterprise-provisioned devices such as the **Acer One 8 T4-82L-G2** ([Acer T4-82L-G2 Manual](https://manuals.plus/acer/one-8-t4-82l-g2-4g-calling-tablet-manual), [Acer One 8 T4-82L Specs](https://www.bajajfinserv.in/acer-one-8-t4-82l-price-in-india)).

## 1. The Four Android Privilege Tiers

| Privilege Tier | How It Is Granted | What It Can Do | What It Cannot Do |
| :--- | :--- | :--- | :--- |
| **1. Ordinary Third-Party App** (`NoobFree` default) | User installs APK; grants manifest permissions (`QUERY_ALL_PACKAGES`, `REQUEST_DELETE_PACKAGES`, `SET_WALLPAPER`). | • Inspect installed apps, active admins, and visible [UserManager](https://developer.android.com/reference/android/app/admin/DevicePolicyIdentifiers) restrictions.<br>• Launch Android's uninstall confirmation (`ACTION_DELETE`) for non-admin user apps.<br>• Set Home & Lock wallpapers when `DISALLOW_SET_WALLPAPER` is false.<br>• Open `About tablet` (`ACTION_DEVICE_INFO_SETTINGS`) for the 7-tap Developer Options flow. | • Cannot silently uninstall apps.<br>• Cannot deactivate another app's `DeviceAdminReceiver`.<br>• Cannot write `Settings.Global` keys directly.<br>• Cannot simulate 7 taps inside the Settings app. |
| **2. Legacy Device Administrator** (`NoobFreeAdminReceiver`) | User explicitly approves `DevicePolicyManager.ACTION_ADD_DEVICE_ADMIN`. | • Lock screen immediately (`dpm.lockNow()`).<br>• Request local data wipe (`dpm.wipeData(0)`) on pre-Android 14 devices when permitted by policy.<br>• Deactivate its own admin role (`dpm.removeActiveAdmin()`). | • **Does NOT equal Device Owner.**<br>• Cannot remove Google Android Device Policy or Halo Agent.<br>• Cannot override `DISALLOW_DEBUGGING_FEATURES` or `DISALLOW_UNINSTALL_APPS`.<br>• On Android 14+ (API 34+), `wipeData(0)` is restricted for ordinary admins ([DevicePolicyManager](https://developer.android.com/reference/android/app/admin/DevicePolicyManager)). |
| **3. ADB Shell via Shizuku (`UID 2000`)** | User enables Developer Options + Wireless/USB Debugging and starts [Shizuku](https://github.com/RikkaApps/Shizuku-API). | • Disable/enable non-critical system bloatware for User 0 (`pm disable-user --user 0 <pkg>` / `pm enable <pkg>`).<br>• Toggle `development_settings_enabled`.<br>• Set system animation scales (`0x`–`2x`) and background process limits. | • Cannot remove an active **Device Owner** (`SecurityException: Cannot remove active admin`).<br>• Cannot bypass `UserManager` restrictions enforced by a Device Owner. |
| **4. Device Owner / Profile Owner (MDM / DPC)** | Provisioned on an unconfigured device during factory setup (QR code, Zero-Touch, NFC, or `dpm set-device-owner` before accounts are added). | • Full device management (`com.google.android.apps.work.clouddpc`, `Halo Agent`).<br>• Block app uninstallation via `dpm.setUninstallBlocked()`.<br>• Enforce `DISALLOW_DEBUGGING_FEATURES`, `DISALLOW_SET_WALLPAPER`, `DISALLOW_FACTORY_RESET`. | • Cannot be granted to an already-set-up personal tablet without factory provisioning.<br>• Cannot be forcibly stripped by another third-party APK. |

## 2. Why Uninstalling Google Device Policy or Halo Apps Shows Specific Android Errors

### Case A: `"Can't uninstall active device admin app"` (Google Android Device Policy / Halo Agent)
- **Cause**: Android's `PackageManagerService` refuses to uninstall any package that has an active `DeviceAdminReceiver` registered in `DevicePolicyManager`.
- **When it IS removable by the user**: If the app is only an **Ordinary Device Administrator** (and *not* a Device Owner or Profile Owner), the user can open **Settings -> Security -> Device admin apps** (via NoobFree's *"1. Deactivate in Admin Settings"* button), tap **Deactivate**, return to NoobFree (*"2. Recheck"*), and then tap **Uninstall**.
- **When the Deactivate button is greyed out**: If Android Settings greys out the **Deactivate** button on `Google Android Device Policy` or `Halo Agent`, that package is either the **Device Owner**, **Profile Owner**, or protected by an active `DevicePolicyManager` policy. An ordinary app cannot un-grey that button. The user must open the management app (`Google Android Device Policy` or `Halo Agent`) to check for an in-app **Unregister / Unenroll** action, or request device release from the organization that enrolled the tablet.

### Case B: `"App is required by the device administrator"` (e.g., Halo ThreatX)
- **Cause**: Even if `Halo ThreatX` is not a `DeviceAdminReceiver` itself, the controlling Device Owner or Profile Owner (`Google Android Device Policy` or `Halo Agent`) has called `DevicePolicyManager.setUninstallBlocked(adminComponent, "com.<halo_threatx_pkg>", true)`.
- **Legitimate Resolution**: Companion apps locked with `setUninstallBlocked` cannot be uninstalled while the controlling administrator remains active. Once the primary administrator unenrolls the tablet or clears `setUninstallBlocked`, Android unlocks standard uninstallation for all companion packages.

## 3. Factory Reset & Zero-Touch Re-Enrollment Warning
- Performing a factory reset (either via Settings/DevicePolicyManager or via Android Recovery Mode hardware keys) erases the `/data` partition.
- However, if the tablet's hardware serial number or IMEI is registered with **Android Zero-Touch Enrollment** or an institutional MDM server (such as government/educational tablet distribution programs), Android's setup wizard automatically contacts Google's provisioning servers as soon as Wi-Fi or SIM data connects and re-installs the management policy.
- Only the enrolling organization or distributor can permanently remove a device's serial/IMEI from a Zero-Touch portal.
